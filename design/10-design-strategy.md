## 1. ระบบนี้ทำอะไร (ไม่เกิน 4 บรรทัด สำหรับ Dev)

ผู้พบของ/เจ้าหน้าที่บันทึกรายการสิ่งของเข้าสู่คลังส่วนกลางโดยผ่านการเบลอร์ภาพและซ่อนข้อมูลส่วนบุคคล (PDPA) → ผู้ทำของหายค้นหารายการและส่งคำร้องยืนยันความเป็นเจ้าของพร้อมแนบหลักฐาน (≤ 10MB) ผ่านช่องทางส่วนตัว → เจ้าหน้าที่ตรวจสอบหลักฐานแบบ Role-based และตัดสินเปลี่ยนสถานะ (Verified / Rejected พร้อมระบุเหตุผล) → ผู้ทำของหายติดต่อรับมอบสิ่งของจริงหน้างานและเจ้าหน้าที่บันทึกปิดงานเป็นสถานะ Returned → ทุกการเปลี่ยนสถานะมี Audit Log ตรวจสอบได้

**ผู้ใช้หลัก:** ผู้ทำของหาย (Requester), ผู้พบของ (Finder), เจ้าหน้าที่ศูนย์รับของหาย (Staff), ผู้ดูแลระบบ IT (IT Admin)

## 5. ข้อตกลงที่ W11 ต้องรักษา (ยังไม่เลือกสถาปัตยกรรม/เทคโนโลยี)

1. **กติกาความปลอดภัยอยู่ที่ API ส่วนกลาง** — การตรวจขนาดไฟล์แนบ (≤ 10MB), การบังคับสิทธิ์ RBAC, การเซ็นเซอร์ภาพ และการควบคุม State Guard ต้องอยู่ที่ API Application เพื่อให้ทุก Client (Web/Mobile) ปฏิบัติตามมาตรฐานเดียวกัน
2. **State เป็นข้อมูลที่บันทึกได้** — สถานะคำร้อง (`pending`, `verified`, `rejected`, `returned`) และสถานะสิ่งของในคลัง ต้องบันทึกเป็นคอลัมน์ในฐานข้อมูลพร้อม Timestamp ไม่ใช่ค่าชั่วคราวใน UI
3. **การเข้าถึงหลักฐานต้องผ่านการยืนยันสิทธิ์** — ไฟล์หลักฐานความเป็นเจ้าของต้องถูกเก็บใน Secure Storage ที่ไม่อนุญาตให้เปิดดูด้วย Direct URL สาธารณะ
