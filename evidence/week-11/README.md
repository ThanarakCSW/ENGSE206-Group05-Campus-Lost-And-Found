## สรุปข้อซักถามจากกลุ่มคู่ตรวจและการตอบของทีม

1. **คำถามบังคับ: driver ที่ห้ามพลาดของทีม อยู่ container ไหน?**
   - **คำตอบ:** D1 (Privacy Leak) และ D2 (Pending Gate) อยู่ที่ **API Application** เป็นหลัก โดย API ทำหน้าที่เบลอร์ภาพส่วนบุคคล เซ็นเซอร์เลขบัตร และควบคุม State Transition Guard ไม่ให้เปลี่ยนสถานะเป็น Verified จนกว่าเจ้าหน้าที่จะอนุมัติ ส่วน D3 (Audit Log) API บันทึกคู่กับทุก Transaction ลงใน **Database (PostgreSQL)**
2. **ข้อดี/จุดเด่น (Sticky เขียว):** การแยก Public API / Private API และการแยก File Storage ระหว่างภาพที่เบลอร์แล้วกับไฟล์หลักฐานส่วนบุคคลชัดเจน สอดคล้องกับ PDPA
   - **คำตอบ:** ทีมคงโครงสร้างนี้ไว้ตาม Done Checklist ข้อ 2
3. **ข้อควรปรับปรุง (Sticky เหลือง):** DEC-01 ควรอ้างถึง BR-CLF-01 เรื่องการเบลอร์ภาพด้วย ไม่ใช่อ้างแค่ NFR-CLF-01
   - **คำตอบ:** **แก้แล้ว** — ทีมปรับแก้ข้อความใน Decision Card DEC-01 ในเอกสาร Word หัวข้อ 6 และในสรุป Markdown ให้ระบุทั้ง BR-CLF-01 และ NFR-CLF-01 เรียบร้อยแล้ว
4. **คำถามชวนคิด (Sticky ชมพู):** หากมีผู้ส่งไฟล์ขนาดใหญ่พร้อมกันหลายไฟล์ ระบบป้องกัน server ล่มอย่างไร
   - **คำตอบ:** API Application มี File Size Validator สกัดกั้นไฟล์ที่เกิน 10MB ทันทีตาม CT-01 และมี Rate Limiter ป้องกันการยิงคำขอซ้ำซ้อน โดยสตรีมไฟล์ตรงไปยัง Secure Object Storage
